# VSDX overnight loop — operating guide

Read this **and** `openspec/vsdx-benchmarks.md` before doing anything. This file is
the environment and process contract; the benchmarks file is the running state.

## Environment

Every shell needs both of these. `cargo`, `rustc` and `wasm-pack` are **not** on the
default PATH:

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
$env:VSDX_CORPUS_DIR = "G:\Heinrich\Dokumente\vsdx-corpus"
```

Installed and pinned: rustc 1.97.1 (msvc), wasm-pack **0.15.0** (do not bypass the
pin), maturin 1.14.1, pytest 9.1.1, bun 1.3.9.

## The corpus is proprietary

`VSDX_CORPUS_DIR` holds the user's real work diagrams. **Never commit them, never
copy them into the repo, never paste their contents into a report.** The repo is
open source. Tests skip gracefully when the variable is unset, which means a run
without it silently loses the most valuable coverage — always set it.

Committed fixtures are synthetic, generated by `scripts/create-vsdx-fixture.ts`
with a fixed zip date for deterministic bytes.

**Never put the corpus under `%LOCALAPPDATA%\Temp`.** It lived in a scratchpad directory
there until 2026-08-15, when a temp cleaner reclaimed it mid-run. Worse than losing it: with
`VSDX_CORPUS_DIR` still *set* but the path gone, corpus tests do not skip — they **fail**
with OS error 3, which looks like a code regression and is not one.

**Filenames are load-bearing.** The tests hardcode `lichtsysteme.vsdx` and `soundplan.vsdx`
in 17 places, including stale-oracle exclusion keys tied to specific shape ids. The restored
originals are named `Lichtsysteme System.vsdx` and `SoundplanMPP68.vsdx`, so the directory
currently also holds copies under the expected names. Either keep those copies, rename the
originals, or update the hardcoded references — but do not let the names drift.

## Dispatch order

Writing is done by low-tier models only; review is read-only and high-tier.

1. **qwen** — `opencode run -m bailian-cli/qwen3.8-max-preview "$(cat prompt.md)" < /dev/null`
   The `< /dev/null` is **mandatory**. Without it opencode hangs forever with no
   output and no error; this cost about an hour on 2026-08-15.
2. **codex** — `codex exec ... -c model_reasoning_effort=medium - < prompt.md`
   Same class of bug: pass the prompt on stdin, not as a positional argument.
3. **Sonnet subagents** — when both are out of quota.

## The full gate

Run all of it before any commit. A narrower gate hid a failing test for nine
consecutive review rounds:

```
cargo test -p betteroffice-vsdx -p betteroffice-vsdx-eval -p betteroffice-vsdx-resolve -p betteroffice-vsdx-render -p betteroffice-vsdx-formula
cargo test -p betteroffice-vsdx-edit -p betteroffice-vsdx-parse --features wasm
cargo fmt --check
cargo clippy --all-targets -- -D warnings
bun run build:vsdx-wasm
bun test packages/vsdx packages/vsdx-react packages/vsdx-i18n
bun test apps/web/app
bun test apps/demo/lib
bun run --filter './packages/*' typecheck
```

`-p betteroffice-vsdx` is the one that was missing. Keep it.

### Known-good failures — ignore these, they are not yours

Verified identical at base commit `f1439b4`:

- `packages/xlsx`, `packages/docx`
- `crates/docx-layout` — two CRLF/LF snapshot tests, caused by `core.autocrlf=true`
  with no `.gitattributes`. Any Windows checkout hits this; Linux CI passes.
  **Never touch `crates/docx-layout`.**
- three failures under `bun test scripts`

### If `packages/vsdx` tests fail with "Cannot find module './generated/vsdx_wasm.js'"

The wasm bundle is a gitignored build artifact and is simply missing. Run
`bun run build:vsdx-wasm` and re-run. This is not a code defect.

### A build dirties the tree with generated bindings — check before assuming CRLF

The `.d.ts` files under `packages/*/src/wasm/generated/**` are **tracked**, not gitignored.
Anything that triggers a wasm build — `bun run build:*-wasm`, or `bun test`, whose `pretest`
builds xlsx and docx — rewrites them and leaves the working tree dirty across all four
packages.

Most of that churn is harmless CRLF noise from `core.autocrlf=true` and reverts cleanly. But
on 2026-08-15 a build produced a **real** 500-line diff in
`packages/docx/src/wasm/generated/edit/docx_edit.d.ts`: the committed file is **stale**
relative to its source. `crates/docx-edit/src/wasm.rs:2939` reads "marks clear so the split",
while the committed binding still carries older, longer wording — someone edited the Rust doc
comment without regenerating the binding.

That is a docx problem, out of scope for vsdx work, and it was reverted rather than carried
on a vsdx branch. Recorded because the symptom looks alarming and is mostly not your doing.
**Run `git diff --numstat` before assuming it is CRLF**; an empty diff with only a warning is
line-ending churn, but non-trivial line counts mean something is genuinely stale.

## Commit rules

- English, scoped conventional: `type(scope): summary`, scope `vsdx` for engine work.
- **No AI co-author trailer of any kind.**
- **Never push. Never open a pull request.**
- Do not commit unless the whole gate is green. Stopping with honest partial work
  beats a green-looking commit.
- Report a gate as passing **only** after running it and seeing it pass. Claiming
  unrun tests has happened repeatedly and is the fastest way to lose the night.

## Scope

In scope: `crates/vsdx-*/**`, `crates/betteroffice-vsdx*/**`, `crates/ooxml-redact*/**`,
`packages/vsdx*/**`, `apps/demo/**`, `apps/web/**`, `apps/docs/**`, `apps/redact-worker/**`,
`bindings/python-vsdx/**`, `scripts/create-vsdx-fixture.ts`, `openspec/**`.

Do not modify other formats' crates or packages.

## The recurring defect class

Nine review rounds each found a different instance of one bug: **the live render
projection and the save projection disagreeing about the same state.** They are now
unified behind a shared serializability predicate. When adding anything that touches
shape identity, ordering or cell values, ask whether both projections still agree —
and prefer making divergence impossible by construction over adding another check.

Related: identity fields (`id`, `pageId`, `sourceId`, `origin`, `parentId`) are
write-once and immutable to remote updates. Do not add a code path that mutates them.

## Public capability copy is a contract

`apps/web/public/llms.txt`, `apps/web/app/content.ts` and `README.md` state what the
product does. Every capability added must update them in the same commit; every
capability removed likewise. Never claim: stencil picker, connector-drag UI,
resize-handle UI (resize is Shift-drag only), NURBS editing, data graphics, data
record sets, containers/lists, validation rules, actions/events, or VBA.
