# BetterOffice

## Comments

NO inline comments unless the code is not understandable without them. Docstrings must be extremely concise.

## Titles

PR and commit titles use scoped conventional commits: `type(scope): summary`. Scope is the affected area — a format (`docx`, `xlsx`, `pptx`, `vsdx`), a shared crate (`opc`, `text`), or an area (`ci`, `deps`, `web`, `agents`). Keep the summary concise and imperative.

Examples: `feat(docx): layout engine`, `fix(xlsx): formula precedence`, `ci(deps): bump actions/checkout`.

## PR style

PR bodies follow this template:

```
TL;DR:
<human (!) written tl;dr of the pr>

Before/After:
<only for visual changes: before and after screenshots>

Repro file:
<only for engine fixes/improvements: link to the file that reproduces the issue>

Summary:
<concise bullets, gen'd by agent>

Test plan:
<check-boxes the author must fulfill before pinging for review>
```

Section rules:

- **TL;DR** — written by a human, always. Agents must leave it empty and never fill it in.
- **Before/After**: include only when the PR makes visual changes. Upload before and after screenshots with GitHub CLI or the browser, following the review artifact instructions below. Omit the section entirely otherwise.
- **Repro file** — include only when the PR fixes or improves something on the engine. Link the repro file (e.g. a committed test fixture or an uploaded `.docx`) that demonstrates the issue the PR addresses. Omit the section entirely otherwise.
- **Summary** — concise bullets describing what changed; generated by the agent. What changed, not how.
- **Test plan** — GitHub check-boxes (`- [ ]`). The author must fulfill every box before pinging for review.

## Review artifacts

Upload review screenshots, before/after comparisons, recordings, and logs directly
to the PR. Never commit files solely to display them in a PR. Keep temporary
outputs outside the repository or in ignored paths.

GitHub CLI v2.99.0 and later supports image and video uploads with `--attach`:

```bash
gh pr comment "$PR_NUMBER" --repo openooxml/betteroffice \
  --body-file /tmp/review.md \
  --attach /tmp/before.png --attach /tmp/after.png
```

`gh pr create` and `gh pr edit` also support `--attach`. Local image references
in the body file are replaced with uploaded URLs. Use a newer CLI if the flag is
missing; uploads require push access. See the [GitHub CLI attachment guide](https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli).
For logs and other non-media files, use browser attachments or link CI artifacts.
If uploading is unavailable, mention the limitation; never use git as a fallback.

Keep actual product assets, maintained documentation illustrations, and fixtures
or golden baselines consumed by automated tests. Linking a review screenshot from
a fixture README does not make it a test fixture.
