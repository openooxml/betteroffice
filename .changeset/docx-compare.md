Compare two DOCX files into tracked changes. `compareDocx(original, revised, { author, date })` compares the text of body paragraphs whose structure is unchanged and returns the original with each difference as a tracked insertion, deletion or replacement attributed to `author` at `date` (RFC 3339 with an explicit offset, recorded in UTC), plus `changes` with deterministic ids and the spans they replace in both inputs. Differences are reported by Unicode word or, with `granularity: "char"`, by grapheme cluster; deleted text keeps its formatting and inserted text takes the revised formatting. Only the changed paragraphs' content is rewritten, every other byte and part is the original's, identical inputs return the original bytes, and the result is reopened and checked against both inputs before it is returned. Whole-paragraph additions, removals and moves, ambiguous correspondence, table, control, formatting, style, field and object changes, content an edit cannot carry, existing revisions and differences outside the body are refused with typed diagnostics and never partially redlined; `unsupported: "report"` collects every diagnostic, and `limits` tightens the documented bounds. Native Rust and Python comparison is not available yet.

Tracked tabs, soft hyphens and non-breaking hyphens now save as such instead of being dropped or written as characters, tabs keep their run formatting, consecutive tracked runs of one revision save in one `w:ins` or `w:del`, and a run that leaves its complex-script size or font unset no longer saves them copied from the Latin ones. The Rust package writer can patch body paragraphs by source location while keeping every other part and byte. The new `betteroffice-ooxml-diff` crate holds the bounded token LCS that PPTX proposal previews now share.
