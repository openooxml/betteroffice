`nextColumn` section starts no longer stop a document from opening. `w:sectPr/w:type w:val="nextColumn"` (ST_SectionMark) parsed fine, but the layout engine's `SectionBreakType` had no matching variant, so the section start reached the layout request as a string serde could not deserialize and the whole `layoutDocumentWithRegionsJson` envelope failed — a document using it never rendered at all. Two quieter paths dropped the value before that: the layout bridge mapped it to `None`, and the Yrs seeding pass filtered `sectionStart` through an allowlist that omitted it, so the paragraph kept its `sectPr` but lost the `sectionBreakType` attribute the bridge prefers as a fallback.

A document using `nextColumn` now opens, lays out and saves correctly. A section starting in the next column keeps the column band in force and moves to the next column, deferring its page geometry like a `continuous` break; out of the last column — so always in a single-column section — it falls through to a new page, matching Word and the existing column-break block. A break already sitting at the top of an empty page advances nowhere, so a leading `nextColumn` no longer emits a blank first page, the same idempotence a `nextPage` break has always had. Authoring a new `nextColumn` break from the editor is not part of this change: `insertSectionBreak` still offers only the four types it always has.

Word cannot change page size or column count part-way down a sheet, so a `nextColumn` section that differs in either is promoted to a page break; a section that only changes the column gap keeps the old band to the end of the sheet and its `w:cols` take effect on the next page, which the paginator now queues alongside the page size and margins it already deferred.

Raw or synthetic layout-block input can place an immediate section break on a page no paragraph has been placed on yet. `compute_layout` accepts blocks directly, so `[columnBreak, sectionBreak(nextPage), paragraph]` can reach a genuinely fragment-free sheet whose column cursor has advanced. The live document bridge instead flushes a section-bearing paragraph first, including when it has no runs, and produces `ColumnBreak -> empty Paragraph -> SectionBreak`. The restamp therefore remains necessary for direct layout-block callers and must not be removed as dead code. It applies to `nextPage`, `evenPage` and `oddPage` as well as page-size or column-count promotions from `continuous` and `nextColumn`. The break correctly declines to open a redundant sheet, and the untouched page is re-formed around the incoming section's size, margins, content bounds and furniture. The declared page geometry now agrees with its fragment widths and content capacity, which can also correct the page count.

Column balancing no longer shortens a section that terminates with `nextColumn`. That balanced height belongs to the outgoing region; carrying it into the incoming section truncated the next column and could produce an extra page. The 800×1000 two-column probe with six incoming 100px paragraphs now keeps all six in page 1's 800px-tall second column instead of placing two and pushing four to page 2. The next-column golden now fills page 1's second column through y 896 before spilling, rather than stopping at the outgoing section's y 496 balance limit.

The unused `SectionLayoutTracker` API remains a scheduling model rather than the live paginator path. Its `NextColumn` outcome does not model the promotion and column-region decisions in `handle_section_break`, so its unit tests should not be treated as behavioral coverage until a future change reconciles and wires it.
