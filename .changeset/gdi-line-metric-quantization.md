Add GDI-compatible line-metric quantization and typographic line spacing to the text engine, and harden the single-spacing line box against malformed font tables.

Word's line boxes come from a text stack whose per-font vertical metrics are whole pixels at an integer ppem, while this engine scaled design metrics in pure floating point. The resulting sub-pixel error per line has the same sign for every line set in the same font and size, so it accumulates down a page until a line crosses a page boundary and pagination diverges. `single_line_box` can now reproduce the integer arithmetic: the em size rounds to a whole ppem, then ascent, descent and leading each round to whole pixels before they are summed — rounding the parts, not the total.

Separately, `OS/2` fsSelection bit 7 (USE_TYPO_METRICS) can now hand line spacing to the sTypo family, honored only from table version 4 since earlier versions reserve the bit. The signed `sTypoLineGap` is preserved, including the negative gaps real fonts ship to set lines tighter than ascent plus descent. A typo box that is unusable on its own terms — no ascent, a positively-signed descender, a component past the design ceiling — falls back to the win metrics rather than laying out on a value that cannot be right.

These ride on two independent flags, `CompatFlags::gdi_line_metrics` and `CompatFlags::typo_line_spacing`, **both off by default**. They are deliberately separate: integer ppem is a GDI property while USE_TYPO_METRICS is a DirectWrite one, so bundling them would make a corpus measurement unattributable to either. Whether Word gates either on `w:compatibilityMode` is not established, and the switches exist so a harness can measure all four combinations before any default moves. `FontMetrics` gained `os2_fs_selection` and `os2_version` to support this.

No well-formed font measures differently yet. Malformed ones can: a face that stuffs a negative into the unsigned `usWinDescent` — Apple ships several, at roughly 31 em — now clamps on the default path instead of scaling that value straight through. The input guards tightened there too. A font size of positive infinity previously passed the degenerate-input check and scaled into an infinite line box; it now yields the same all-zero box as NaN and non-positive sizes. Design metrics are bounded to a sane multiple of the em, and the em size to Word's own 1638pt ceiling on **both** paths, since a finite but absurd size overflows even a bounded design value. Font bytes are attacker-controlled, so these are bounds, not style.
